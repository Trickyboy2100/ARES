# Execution authority and temporal adaptation: sources read 2026-11-05

- MP3 (CoRL2023), https://arxiv.org/abs/2306.12729: Sections3.1–3.5 parameterize trajectories with ProDMPs and condition new segments on initial position/velocity; segment duration defines the policy's decision horizon. This precedes smooth replanning and temporal parameter RL. Our experiment retains an existing planner and measured grasp, and tests access to semantic-stage decisions. It is not MP3 reproduction. No verified official MP3 source link was obtained from its project page in this pass.
- Option-Critic, https://arxiv.org/abs/1609.05140: termination gradients depend on option advantage; termination affects call-and-return policy choice. Author implementation https://github.com/jeanharb/option_critic pinned `5d6c81a650a8f452bc8ad3250f1f211d317fde8c`; inspected `neural_net.py` and `train_agent.py`. The critic mixes continuation/switching values; termination is sampled after transitions and its gradient includes an explicit regularizer. Our phase boundary is a fixed executor event, not learned Option-Critic termination. No source copied or installed (no explicit license file found).
- Learning with Options that Terminate Off-Policy, https://arxiv.org/abs/1711.03817: Sections3–5 separate behavior termination from target termination and correct multi-step backups. This directly warns against calling a changed termination policy only an estimator change. We collect separate own-policy data and aggregate measured SMDP transitions under each actual termination. We do not claim Q(beta) equivalence or novelty for reopening Options.
- Policy Decorator, https://arxiv.org/abs/2412.13630: public code https://github.com/tongzhoumu/policy_decorator at `92ba9ba442587ae5989c286355ace2200a0537fb`, `online/pi_dec_bet_maniskill2.py` inspected. Residuals are enabled by a schedule, scaled and added to base actions; reward and truncation-bootstrap conventions differ from native finite-horizon success here. Successful-behavior BC and exploration controls are mature mechanisms, not a claimed full reproduction.
- ROS2 rolling trajectory representation/replacement, https://control.ros.org/master/doc/ros2_controllers/joint_trajectory_controller/doc/trajectory.html: current documentation describes time-anchored splicing and interpolation caveats. It is a version-specific engineering precedent; the ARES simulation does not run this ROS controller. Checking joint limits and maintaining timestamps alone is not a contact-success guarantee.

The technical hypothesis is now narrower: a representation that distinguishes active-reference adaptation from atomic measured-reference adaptation also needs decision opportunities at meaningful execution boundaries. All tested components have precedents. A publishable contribution still requires a well-supported combination and comparative full-task benefit, not renaming phase termination, adding state fields, or adding actions.
