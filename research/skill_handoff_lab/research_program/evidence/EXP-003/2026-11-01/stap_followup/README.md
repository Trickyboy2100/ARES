# EXP-003：STAP算法核复现、两技能物理基线及后验修正负结果

入口：[交互审查页](REVIEW.html)。原始数据、模型、失败、来源哈希均保留。本轮从干净的df268c0工作区正常fetch/fast-forward到a89e5bc；没有reset或改写历史。全部物理实验在GPU0、无网络命名空间中运行，ARES-R只读，无实机操作。

## 研究结论

1. **独立统计复算PASS。** 实际运行新审计脚本，历史task SAC对强搜索35/36 vs32/36，4救回1退化，精确p=.375，六scene聚类区间[−5.56,+22.22]pp。没有把历史小样本差值升格为方法增益。
2. **STAP算法核等价PASS，官方整套benchmark未复现。** 固定官方commit，直接执行原始CEM/评分函数体并与本地移植做12组完整候选流精确对照。旧包缺gym，保留实际报错；未改系统依赖。详见[公式/组件映射及范围](STAP_MAPPING.md)。
3. **真实双技能学习与执行已经接通。** 稳定抓持后再选择钩入参数，真实物理SkillResult进入后段。64个真实训练episode，两个模型版本、合计5600次优化；普通离线Fitted Q、STAP式模型规划、Foresight状态类比均实际执行。它们仍是有界基线pilot，**不是已收敛的强STAP或在线SAC/PPO训练证明**。
4. **最强观察结果是既有STAP序列6/8，不是ARES新方法。** 同前段精确匹配时，加入实测后验重规划降为3/8，0救回3退化（精确p=.25）。改成状态增量预测使工具终态误差从约89–175mm降至10–35mm，任务收益仍未改善。更准的模型与有效的参数修正是两个不同问题。
5. **任务条件依赖仍未识别完整。** 训练参数矩阵中固定105mm/−55mm覆盖8/8上下文；目标扩大至±160mm仍无抓点排序反转。新初态上固定100mm/−65mm为4/8，STAP开环6/8多救回2例（p=.5），但只有两个新scene、同一训练seed，且用于本轮调试。不能推论泛化、独立创新或隐藏状态必要性。

## 为什么现在不训练新的“合同网络”

实际机会已有一个明确线索：**在相同真实SkillResult上，后验价值最优动作可能比原定合法动作更差**。但旧训练集只有两个场景、抓点仅两个端点。真实反馈已在完整状态中，不能将“新增信息”作为创新主张；历史依赖/POMDP也未被证实。

本轮辅助合同和等容量通用辅助代码已写出，但**未训练、未作为结果**。首先要补足已有STAP/同权限RL的真实后段覆盖和校准，否则击败一个过度自信的薄数据模型只是弱基线收益。

实测预算保护在两个案例触发，救回一个（新hook预计184步，原计划62步，剩余61步）。该规则只选择更短的保留候选，**不保证规划预测与接触执行完全一致，也不保证硬预算可行**；另一个保留候选315步仍失败。其他后验退化未被该规则消除。它是强控制增益，非新RL。

### 下一项已具体化的实验

保持本轮冻结控制器与原生100步，用新的训练scene743040–743047，固定两个质量与两个声明目标；有界采用grasp90/100/105mm、hook−55/−65/−75mm的分层设计，先识别真实可执行后段与接触失败。每个首技能执行结果保留，再执行真实后段，禁止用几何标签伪造counterfactual success。预算先限96条（覆盖优先，不把每个组合全穷举）。

在同数据上先训练成熟两边界Fitted Q/STAP与监督评分，检验简单固定或几何策略能否匹敌。若确有条件依赖，唯一候选增量是**合同裕量辅助价值学习决定是否保留原定参数**；与同状态普通RL、STAP、实际后段价值、等容量非合同辅助严格配对，动作权限与物理预算不变。另用未参与控制修理的新scene743050–743053检验；本轮743020/743021不再称独立测试集。尚无独立增益时，不扩大五种子或论文稿件。
