## 1. 唯一目标：一篇真正有方法、有结果的 SCI 强化学习论文

稳定问题不变：

**面对不同工件、目标、抓持状态和接触偏差，机器人能否在复用已有规划器与操作技能的前提下，根据真实技能执行结果，学习调整后续技能参数，从而提高完整多阶段任务的成功、可靠性、学习效率和未见条件适应？**

长期研究对象不是单个 Peg 的 localZ 偏移，也不是单独的 SAC loss，而是：

任务/物体条件 → 前驱技能参数 → 真实物理执行 → SkillResult/后验状态 → 后继技能参数与执行 → 完整任务结果 → 策略更新。

**长程任务是本轮重点探索的实验方向，不是预先认定的新颖性。** 不允许把普通 Option、技能链、下游价值、参数化动作、残差 RL 或长 episode 本身改名为原创方法。

本研究最终要回答：
1. 前驱技能的合法参数是否会改变后续一个或多个技能的可行性？
2. 机器人能否从真实 SkillResult 中识别这种变化，并调整后续技能？
3. 这种调整能否比合理的强规划/规则、固定参数搜索、同权限普通 RL 和监督方法更好？
4. 当技能链变长、任务条件变化时，方法是否能减少错误传播或恢复更多完整任务？
5. 哪个具体机制造成了增益，适用边界是什么？

优先做出一个小而清楚、可复现的正方法；不追求一次解决通用具身智能、VLA、所有技能或实机部署。

## 2. 先统一概念：什么才算长程任务

**长程不是单纯物理步数多，也不是把一个 100 步 episode 延长到 500 步。**

对 ARES，本研究中的长程/多阶段任务必须具有真实的技能决策依赖：
- 至少两个真实、独立、可验证的技能参数决策边界；
- 前驱参数改变实际物体/工具/接触/支撑状态；
- 后继策略必须读取前驱真实执行后的状态，而不是只读取理想计划终点；
- 不同前驱选择可能使后续动作的可行性或价值发生变化；
- 后续技能至少存在一次真实的条件化决策；
- 完整任务成功由原生物理终态判定，不能用 waypoint 到达代替技能完成。

**优先寻找自然具有 3–5 个有效技能决策边界的任务。** 如果现有可复现任务只有两个真实边界，但具有清楚的跨技能因果依赖，也可以作为多阶段主任务；此时论文应准确称为 multi-stage，不夸大为已经解决任意深度 long-horizon。绝不为了凑 4–6 个阶段而添加无物理意义的伪技能。

建议定义“有效决策深度”而非只数 Option 数量：
- 某个早期决策改变后续两个或更多边界的可行性/结果；
- 后续观测确实能影响策略下一次动作；
- 若去掉中间真实 SkillResult 或固定后续决策，完整任务结果发生可重复变化。

可以构建阶段影响矩阵：对每个前驱边界 i，测量改变其参数后，对后续边界 j 的成功、可行性、接触状态、剩余预算和完整任务成功造成的配对变化。只数物理步数、Option 调用数或任务名中的“long horizon”不算证据。

- 六条已记录正向 Option 分支均在 Option 释放前已经达到原生任务成功。

可继承结论：
- 局部参数化 Option 能真实改变完整任务结果；
- 固定 Option 是当前有用的强物理参照；
- 参考/队列/执行时机确实影响物理结果。

不可声称：
- KL/QP/见证约束已形成独立 RL 增益；

**这项工作保留为执行机制和局部技能适应证据，不再让它独自承担整篇长程 RL 论文。**

### 3.2 StackPyramid 历史两阶段真实物理研究（11_PAPER_FIRST_20261028）

这是目前最值得重新核实和继承的多阶段任务资产：

- 64 个训练设计场景中，9 个案例仅改变 A 参数就改变后续结果；
- 18 组案例在相同前段后验下，C 参数改变了后续结果；

- 存在真实前后技能物理依赖；

- 当时风险正则候选优于普通 PPO；

**Codex 必须重新检查 StackPyramid 的剩余 headroom。** 它可能是方法开发和机制研究的好底座，但 best fixed 59/64、hindsight union 62/64 说明原分布剩余空间很小。不得只重复旧 64 场景来制造正结果。

### 4.1 任务适配评分表

每个候选任务至少评估以下项目，并用实际证据打分：

| 维度 | 要回答的问题 |
|---|---|
| 真实技能深度 | 有多少个独立、物理验收的决策边界？是否自然存在 3–5 个？ |
| 前驱—后继因果依赖 | 改变前驱参数是否改变后续技能的成功、可行性或最优参数？ |
| 条件排序变化 | 不同自然条件下，最好的参数/Option 是否发生变化，而非始终同一动作？ |
| 后继恢复空间 | 后续合法动作能否真实救回某些失败，是否也存在有害干预？ |
| 状态可观测性 | Actor 能否在部署时看到区分这些条件的状态？若不能，历史/信念是否有真实辨识价值？ |
| 强基线 headroom | 强 planner、几何规则、固定搜索和成熟 RL 是否仍留下真实但非人为制造的空间？ |
| 物理可复现性 | 能否重复 reset、匹配前缀、保持原生成功判据和预算？ |
| 训练成本 | 规划器/物理执行耗时是否支持有意义的在线训练？ |
| 论文可解释性 | 失败是否来自技能链物理依赖，而非单纯 planner bug 或环境脚本错误？ |
| 第二任务价值 | 是否能用不同物理机制验证同一方法，而不是换皮同一接触动作？ |

不设机械的总分阈值，但必须列出：
- 最适合主任务的候选；
- 最适合备选的候选；
- 每个候选不适合的证据；
- 为什么最终选择的任务比继续扩 Peg 更有方法研究价值。

### 4.2 必须测量“学习空间”，不能只测任务难度

在训练设计场景上做真实、有限、可解释的物理分支实验：
1. 从同一自然 reset 开始；
2. 严格重执行相同的物理前缀；
3. 在真实技能边界记录当前物体/工具/机器人状态和剩余预算；
4. 执行 2–4 个有物理意义的合法参数/Option；
5. 每个分支继续真实执行后续完整技能链；
6. 记录每一阶段是否独立完成、后继条件是否满足、完整任务是否成功、失败阶段、接触/支撑状态、物理时间和规划成本。

优先 32–64 个新的训练设计 root 起步；根据分支差异、reset batch 和实际吞吐扩展。不要把多个同场景分支当作独立任务样本。

计算并报告：
- best fixed parameter / best fixed skill sequence；
- 按可观测任务条件分组的 best fixed；
- 事后已测成功并集（仅为 opportunity upper bound）；
- 各方法相对强基线的 paired rescue/regression；
- 不同前驱参数对后续多个阶段的影响矩阵；
- 条件化策略所需信息是否真实可观测。

若只有 hindsight union 很高，但可观测状态无法区分成功分支，则这是 POMDP/信息不足问题，不能直接宣称策略可学习。若 best fixed 已接近 oracle，尽快换任务条件或任务，不继续扩网络。

禁止用 state setter、teleport、伪造中间成功、只重放 pose、改变原生 success 或超时标准来制造分支差异。若使用严格匹配的缓存规划，只能缓存候选计划，不能缓存物体状态或结果；实际对象每次都必须完整运行物理。

## 5. 选择任务后，围绕一个核心方法假设推进

Codex 可以读论文、官方代码、分析轨迹、提出理论、修改模块和训练。不要预设某一个算法名称。每个候选机制都必须能回答：它具体解决什么已有方法没有解决或没有充分验证的问题？

优先考虑以下假设，**竞争而非同时堆叠**：

### H1：真实 SkillResult 条件化的后继技能策略

策略输入包含任务条件、当前阶段、实际前驱执行结果、下游技能合同和剩余预算：
\[
\pi_\theta(\omega_k \mid c, o_k, \mathrm{SkillResult}_{0:k}, b_k).
\]

检验：真实前驱结果是否能让后继策略选择不同合法参数，并改善完整技能链，而不是只提升前段成功率。

### H2：下游可行性/后续价值驱动的技能边界选择

技能级价值可以写为：
\[
Q_k(z_k,\omega_k)
=
\mathbb E\left[
R_k+\gamma^{\tau_k}V_{k+1}(z_{k+1}, C_{k+1})
\right].
\]

其中 \(\tau_k\) 是真实 Option 持续时间，\(C_{k+1}\) 是后续技能合同。检验前驱参数是否应该为下游保留更有利的物理终态。

注意 STAP、ViSkill、Foresight Residual RL 已研究下游技能可行性/后续成功价值；不能把这个公式或预测头本身宣称原创。

### H3：技能链中的执行进度/时机自适应

检验何时应继续已有计划、何时刷新参考、何时重新参数化或恢复。必须区分物理时钟、队列游标、Option duration 和真正的技能完成状态。轨迹拼接、平滑重规划、Option termination 均已有先例，不能改名当贡献。

### H4：部分可观测状态下的效果信念

只有在同一合法观测对应不同真实抓持/接触/摩擦状态，且过去动作—结果能辨识该隐藏状态、进而改善未来决策时，才研究 belief/POMDP。先做观测别名和动作可辨识性实验；若完整当前观测已包含相关信息，就不引入无意义历史或 belief 网络。

### H5：保留强策略基础上的条件化策略改进

只有当在线更新明显破坏已有成功行为时，才研究保留/受约束策略更新。必须同时证明新能力的采用和旧能力保持，不能只把动作限制在 witness 集合而不学习采用正向动作。普通 BC/KL/QP/安全回退均有先例，单独不算原创。

**选择规则：**先用物理证据筛掉不成立假设，再选一个最能解释真实收益的核心机制。一次主实验最多引入一个新的核心机制，其他变化作为共同接口或明确消融。

## 6. 理论组织：够用、正确、服务于方法

优先使用技能级 MDP/SMDP：
- 技能决策状态包含当前真实执行状态、任务条件、阶段、SkillResult、剩余预算；
- Option/技能执行有真实持续时间 \(\tau_k\)、终止条件和物理后果；
- 终端任务成功按原生谓词计算；
- 若采用 \(\gamma<1\)，必须正确处理 \(\gamma^{\tau_k}\)；有限时域 \(\gamma=1\) 也可以，但需说明终止和预算；
- 每个技能边界必须由真实释放、稳定、抓持或接触验收定义，不能把 waypoint 当作技能终态。

理论工作优先回答：
1. 前驱技能参数如何通过实际转移影响后继可行性？
2. 多阶段价值如何通过 SMDP 递推？
3. 真实执行反馈何时提供额外信息？
4. 方法的假设、可观测性和失效条件是什么？

不为了论文形式硬造全局安全保证或单调改进定理。若有严格成立的局部性质，可以证明局部命令偏移、Option 合同或价值估计边界；接触模式切换下不成立的地方必须明确。

- 前驱结果如何进入后继决策；
- 使用何种学习算法、监督/搜索/规划数据；
- 强基线与第二任务；
- 哪些结果是完整物理执行，哪些只是规划或模拟；
- ARES 可以合理区别的具体机制和证据。

必须优先读与候选任务最接近的 3–5 篇，并尽可能检查官方代码/配置。不要无限扩展文献清单。若一个候选贡献已被近邻覆盖，主动收缩或改变机制，不通过改名制造新颖性。

## 8. 强基线与公平实验：每个候选必须在相同条件下比较

主任务至少保留：
1. 强名义规划/技能规则；
2. 强几何/解析规则；
3. 最佳固定参数或等预算搜索/CEM；
4. 同观测、同动作权限、同物理预算的普通分阶段 PPO/SAC；
5. 同数据成本的监督评分/行为克隆或 branch ranker（如果物理数据用于监督）；
6. 一个最接近的功能方法对照；
7. ARES 候选方法。

所有方法共享：
- 原生任务成功判据和 episode horizon；
- 合法动作/Option 权限；
- 可观测信息和任务条件；
- 相同的规划器与控制器；
- 匹配的训练物理交互预算和数据权限；
- 相同的开发/封存划分与 checkpoint 选择规则。

所有成本分开记账：
- 完整物理回合与控制步；
- 有效技能决策数；
- Planner/IK 查询与墙钟时间；
- 离线分支采集；
- 监督/预训练数据；
- Actor/Critic 优化步；
- 失败工程运行、padding、缓存计划成本。

不能让候选拥有额外搜索、隐藏仿真真值或更多物理分支，却只比较优化器步数。

## 9. 连续自主迭代：不要停在诊断报告，也不要盲目扩训

每轮使用以下闭环：

**问题 → 可证伪假设 → 最近邻/理论 → 最小真实物理对照 → 学习器训练 → 冻结评价 → 机制解释 → 下一次方法修订。**

Codex 有自主权：
- 自主读论文、源码和配置；
- 自主重分析全部历史正负轨迹；
- 自主选择、修改或放弃候选任务；
- 自主提出多个方法假设并筛选；
- 自主实现/重构 Option、SkillResult、观测、奖励、训练器；
- 自主做数学推导、反例和复杂度/成本分析；
- 自主运行真实物理分支、在线训练和强基线；
- 根据证据连续完成 2–3 次有意义的研究迭代；
- 如果主任务不适合，可以转向最合适的真实物理任务，但必须保留原任务的完整负结果和资产；
- 不必每个小改动都等待用户或 ChatGPT 批准。

**自主不等于无边界。** 每次重大方法改变前，先说明它将区分哪两个解释；每轮优先选择“论文价值/物理成本”最高的实验，而不是实验数量最多的方案。

遇到负结果时：
- 任务没有条件依赖/可恢复机会 → 转任务或转任务条件，不盲训；
- 动作能改变物理但策略不学习 → 检查动作覆盖、状态可辨识、探索和数据支持；
- 普通 RL 与候选相同 → 不宣称新算法，找真正缺失的机制；
- 候选只提高单个 seed → 扩展独立初始化或修订方法，不直接投稿；
- 固定规则/搜索已解决 → 保留它作为强基线，转向它解决不了的合法条件；
- 只有训练集/开发集成功 → 不能称泛化；
- 发现正向方法信号 → 不再无止境添加新模块，冻结候选并进入确认。

**不允许以下循环：**
- 每轮都新增一个 loss/预测头/门控/QP/KL，却没有新的物理学习机会；
- 把更多梯度更新当作更多有效训练；
- 反复在已看过的 8/16/24/32/64 场景上调到最好；
- 只做诊断 Gate，诊断结束后不继续最有价值的实际方法尝试；
- 为制造正收益而弱化名义控制、缩短预算、修改成功判据或筛选有利初态；
- 把 oracle union、事后并集、固定策略或单案例救回写成 RL 成绩。

## 10. 训练与评价的阶段安排

### Phase A：任务发现与筛选
- 复核历史 StackPyramid、Peg、Charger 和现有多阶段资产；
- 检查当前代码库是否有真正可运行的工具使用、交接、重复抓放或双臂技能链；
- 建立任务适配矩阵；
- 选择一个主任务、一个备选任务；
- 先冻结强名义控制，不因候选失败而削弱基线。

### Phase B：真实长程物理机会图
- 在新的训练设计初态上做匹配前缀分支；
- 逐阶段验证 SkillResult；
- 估计前驱参数对多个后继阶段的影响；
- 测量是否存在动作排序变化、真实救回与有害干预；
- 区分前段失败、handoff 失败、后继失败和完整任务失败；
- 如果任务饱和，立即转向有物理依据的适应变体或备选任务。

### Phase C：强基线和一个核心方法候选
- 先跑成熟同权限 RL 和强非 RL 规则/搜索；
- 从物理机会图选择一个最有依据的机制；
- 采用共享的成熟 Option/SMDP 基础，不必为创新而重写 SAC/PPO；
- 至少两个独立网络初始化开展 pilot；
- 每个学习臂从相同初始化/同等预训练基础开始；
- 记录完整自身策略数据，而不是只在冻结规则分支上训练。

### Phase D：方法迭代
- 根据 Actor 实际部署行为而非只看 Critic/Q 指标分析；
- 检查学习器是否改变了真实阶段决策；
- 检查新能力是否来自额外动作、额外数据、状态信息或方法机制；
- 一次只增加一个核心机制；
- 如果第一轮有正趋势，扩大到至少三个、条件允许时五个独立训练 seed；
- 如果没有正趋势，必须给出下一种有依据的方法或任务选择，不无限延长相同训练。

### Phase E：论文确认
冻结方法、超参、checkpoint 选择和评价协议后：
- 生成全新、此前未用于方法选择的自然场景组；
- 至少 3 个独立训练 seed，正式主张应根据统计设计决定是否需要 5 个或更多；
- 保留 sealed test，只有方法冻结后才按预先协议开启一次；
- 至少一个不同物理机制的第二任务；
- 若声称感知/部分可观测，增加真实视觉/点云结构化估计或受控噪声/延迟验证；
- 仿真 Panda 结果不得冒充 JAKA 实机或 ARES-R 部署结果。

预算由实际吞吐和物理机会决定，不机械要求固定回合数。每轮 pilot 可以使用 32–64 个新训练 root、每学习臂 128–256 个自身策略回合作为起点，但这些只是资源规划，不是统计充分性的证明。有效物理分支数量、训练种子和独立 scene/reset batch 更重要。

## 11. 论文级指标和统计要求

主指标：
- 原生完整任务成功率；
- 配对救回/退化；
- 按场景组和训练 seed 分层的不确定性。

长程专属指标：
- 每个技能边界的真实验收率；
- 条件后继成功率：P(后继技能完成 | 前驱真实验收通过)；
- 各阶段失败风险/错误传播；
- 前驱参数对后续 1、2、多个阶段的因果影响；
- 整条技能链成功率随决策深度/阶段数的变化；
- 失败恢复率与恢复后剩余预算；
- 每次成功的物理步、规划调用、技能决策和训练交互成本；
- 训练数据效率及不同任务条件的泛化。

统计：
- 同一场景的多动作、多分支、多 seed 不能都算独立任务样本；
- 场景/reset batch 与训练 seed 分开分析；
- 使用配对结果、适当的 bootstrap/McNemar 或层级模型；
- 同一场景的多策略结果保留配对结构；
- 不用训练/开发场景冒充 sealed；
- 结果不确定时如实报告区间，不只报成功数；
- 若方法收益来自成本而不是成功率，必须在看 sealed test 之前明确预注册成本主张。

## 12. 论文同步：现在开始积累主干，不要等所有实验完成

保持一篇论文、一个核心问题。现有 MANUSCRIPT.md 作为研究历史和累计草稿保留；当任务与方法选择稳定后，另建干净投稿稿件，避免把所有历史失败塞进正文。

论文结构建议：
1. Introduction：长程操作中前驱物理结果影响后续技能，局部成功不保证整链成功；
2. Related Work：hierarchical RL、skill chaining、task-conditioned parameterization、downstream feasibility、residual/recovery RL；
3. Problem Formulation：真实 SkillBoundary、SkillResult、Option/SMDP、完整任务目标；
4. Method：只写经实验验证的核心机制；
5. Experimental Setup：真实物理任务、强规划/规则、同权限 RL、数据/预算；
6. Main Results：完整链成功、阶段条件成功、救回/退化、学习曲线；
7. Mechanism/Ablation：前驱结果、后继条件、Option 时机/执行合同等关键因素；
8. Generalization/Limitations：第二任务、未见条件、感知限制和仿真边界。

可能的工作标题：
**Execution-Conditioned Hierarchical Reinforcement Learning for Multi-Stage Robotic Manipulation**
或
**Task-Conditioned Skill-Boundary Reinforcement Learning for Long-Horizon Manipulation**

标题不是研究结论，不提前锁定。

论文贡献必须具体，例如：
- 一种基于真实执行结果、任务条件和下游技能合同的参数化技能策略；
- 一种有证据支持的技能边界/执行反馈学习机制；
- 在真实物理长程任务上相对强规划、固定搜索、普通同接口 RL 的完整任务增益；
- 在第二种物理机制或未见任务条件下的适用性证据。

如果没有独立方法增益，不得将系统集成或普通 RL 结果包装成“新算法”。可以保留有价值的实证/系统论文可能性，但必须重新判断其是否达到目标 SCI 期刊的贡献门槛。

## 15. 给 Codex 的直接启动命令

请按本文件、research/skill_handoff_lab/AGENTS.md 和 research_program/README.md 自主继续 ARES 一篇 SCI 方法论文。

不要只做文献综述或任务筛选报告。先核实最新 HEAD、同步 STATE 和活动实验，再完成长程/多阶段任务资产审查，选出最有研究价值的主任务与备选任务。用真实原生物理分支验证前驱—后继依赖和可学习机会；若任务空间有价值，立即建立强基线并训练一个有物理证据支持的核心方法候选。若任务不合适，基于证据转向，不为维护旧实验而盲训。

你可以自主阅读论文和官方代码、做理论分析、修改模块、改变合法任务参数、训练 PPO/SAC/Option 或提出新的学习机制、开展真实物理实验、分析失败并连续迭代。允许在一次会话中完成多个有科学价值的迭代，不必每个小步骤等待用户批准。
